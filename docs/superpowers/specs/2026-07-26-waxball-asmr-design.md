# 왁뿌볼 ASMR — 설계 문서

작성일 2026-07-26

## 1. 무엇을 만드는가

왁스 뿌시기 볼(왁뿌볼)을 화면에서 굴리고 문질러 까면서, 그때 나는 "빠자자작" 소리를 듣는
안드로이드 촉감/ASMR 앱. 소리는 녹음 재생이 아니라 **매 순간 실시간 합성**한다.

성공 기준은 하나다. **눈 감고 소리만 들었을 때 진짜 왁뿌볼 부수는 소리로 들려야 한다.**
그래픽·미션·수집은 전부 그 소리를 계속 듣게 만들기 위한 장치다.

주 사용자는 초등 고학년 이상~어른. 스트레스 해소용으로 어른이 써도 재미있는 수준을 목표로 한다.

## 2. 기술 선택과 그 이유

| 항목 | 선택 | 이유 |
|---|---|---|
| 렌더링 | GLSurfaceView + OpenGL ES 3.0 직접 구현 | 게임엔진 없이. APK 최소, 오디오 경로를 직접 통제. 3D 요소가 볼 하나뿐이라 엔진 이점이 없음 |
| 오디오 | 순수 Kotlin 합성 + AudioTrack 저지연 모드 | 이 PC에 NDK/CMake 미설치(SDK 확인 완료). Oboe는 NDK 1GB+ 설치 전제라 빌드 재현성 리스크가 큼 |
| UI | Views + ViewBinding, Material3 다크 | WordChain과 동일 스택 |
| 언어/빌드 | Kotlin (AGP 9.2.1 내장), compileSdk 36, minSdk 26 | 기존 프로젝트와 동일 |
| 물리엔진 | 사용 안 함 | 필요한 물리는 "떨어진 조각의 중력·회전"뿐. 200줄이면 충분 |

### 오디오 지연 목표와 근거

목표: 터치 → 소리 출력 **30ms 이하**. 손가락 동작과 소리가 어긋나면 뇌가 가짜로 인식해
ASMR 효과가 통째로 사라진다. 체감 임계는 약 40ms.

달성 수단:
- `AudioTrack` + `PERFORMANCE_MODE_LOW_LATENCY` + `ENCODING_PCM_FLOAT`
- 샘플레이트/버퍼는 `AudioManager.PROPERTY_OUTPUT_SAMPLE_RATE`,
  `PROPERTY_OUTPUT_FRAMES_PER_BUFFER`에서 기기 네이티브 값을 읽어 사용
- 버퍼 크기 = 네이티브 프레임 × 2 (언더런 발생 시 ×3으로 자동 상향, 1회만)
- **오디오 스레드에서 객체 할당 금지.** 모든 버퍼·그레인은 사전 할당된 원시 배열 풀.
  GC가 오디오 콜백을 멈추면 뚝뚝 끊긴다. 이건 타협 대상이 아니다.
- `Process.setThreadPriority(THREAD_PRIORITY_URGENT_AUDIO)`

측정: 실기기에서 터치 타임스탬프와 오디오 프레임 인덱스 차이를 로그로 남겨 확인한다.
30ms를 못 맞추면 그때 NDK+Oboe 도입을 재검토한다.

## 3. 구조

```
com.waxball.asmr
├── core/      순수 Kotlin. 안드로이드 의존 없음 → JVM 유닛테스트 대상
│   ├── Icosphere.kt      구 메시 생성 (세분화 단계별)
│   ├── ShardSplitter.kt  구면 보로노이 분할 → shard 메시 + 인접 그래프
│   ├── BreakModel.kt     shard 상태머신, 압력 누적, 균열 전파, 이벤트 방출
│   ├── BreakEvent.kt     파괴 이벤트 (소리·시각이 공유하는 단일 진실)
│   ├── BallSpec.kt       볼 1종의 정의 (크기·두께·모양·재질 → 파라미터)
│   ├── BallCatalog.kt    볼 30종 정의
│   ├── Missions.kt       미션 정의 + 판정기
│   └── Progress.kt       도감·코인·해금 상태 (저장소는 인터페이스로 분리)
├── audio/
│   ├── Grain.kt          크랙 그레인 1개의 합성 (노이즈 버스트 + 공명)
│   ├── Biquad.kt         밴드패스 필터
│   ├── Synth.kt          그레인 스케줄러 + 믹서. 오프라인 렌더 가능 → 테스트 대상
│   ├── AudioEngine.kt    AudioTrack 스레드. Synth를 실시간으로 돌림
│   └── Haptics.kt        그레인에 맞춘 짧은 진동
├── gl/
│   ├── BallRenderer.kt   씬 그리기
│   ├── Shaders.kt        GLSL 소스
│   ├── Mat4.kt / Vec3.kt 최소 수학
│   ├── Picker.kt         화면 터치 → 광선 → shard 히트 판정
│   └── Debris.kt         떨어진 조각 낙하·누적
└── ui/
    ├── HomeActivity      볼 고르기 / 미션 진입
    ├── PlayActivity      플레이 화면 (모드 무관 공통)
    ├── InputRouter.kt    터치를 깨기/굴리기/문지르기로 분류
    ├── CollectionActivity 도감
    └── SettingsActivity  진동·음량·조각 수·굴리기 잠금
```

**핵심 원칙**: `core/`와 `audio/Synth`는 안드로이드 API를 일절 쓰지 않는다.
파괴 로직과 합성 로직 전체를 PC에서 JVM 테스트로 검증할 수 있게 하기 위해서다.
이 두 곳이 앱의 본체이므로, 여기가 테스트되면 나머지는 배선 문제일 뿐이다.

### 데이터 흐름

```
터치 → InputRouter → (깨기라면) Picker로 shard 특정
                          ↓
                     BreakModel: 압력 누적 → 상태 전이 → BreakEvent 방출
                          ↓                              ↓
                   BallRenderer (조각 갈라짐/낙하)    Synth (그레인 폭발)
                                                        ↓
                                                     Haptics
```

`BreakEvent`가 유일한 접점이다. 렌더러와 신스는 서로를 모른다.
덕분에 소리만 따로 테스트할 수 있고, 소리를 고쳐도 그래픽이 안 깨진다.

## 4. 소리 설계

### 왜 합성인가

녹음 파일은 몇 번만 들으면 귀가 "아까 그 소리"라고 알아챈다. 그 순간 ASMR이 죽는다.
또 손가락 힘·속도에 따라 소리가 변해야 하는데 녹음으로는 불가능하다.

### 모델: 그래뉼러 크랙 합성

실제 왁스 파쇄음은 한 번의 "빵"이 아니라, 수백 개의 미세 파열이 불규칙 간격으로
연달아 터지는 임펄스 열이다. 그래서 "빠자자작"으로 들린다. 이걸 그대로 모사한다.

**그레인 1개** = 밴드패스 필터를 통과한 노이즈 순간 폭발 + 짧게 감쇠하는 공명음

| 파라미터 | 범위 | 의미 |
|---|---|---|
| attack | 0.2~1ms | 딱 하고 서는 앞머리 |
| decay | 5~40ms | 여운 |
| centerFreq | 800Hz~9kHz | 재질·조각 크기 |
| Q | 2~12 | 뾰족함 |
| resonance | 0~1 | 공명음 섞는 비율 (큰 조각일수록 높음) |
| pan | -1~1 | 터치 x좌표에서 결정 |
| amp | - | 압력·조각 크기 |

**행동 → 그레인 분포**

| 행동 | 그레인 수 | 분포 |
|---|---|---|
| 살살 탭 | 5~20 | 성기게, 진폭 작게 |
| 꾹 누름 | 50~200 | 촘촘히, 압력에 비례해 밀도 증가 |
| 문지름 | 손가락 속도 비례 연속 | 끊기지 않게 계속 방출 — 가장 중독성 있는 구간 |
| 조각 분리 | 1회 강한 그레인 + 공명 | 조각 면적이 클수록 저음·긴 여운 |
| 조각 착지 | 작고 건조한 그레인 2~5 | 별도 레이어로 계속 깔림 |
| 코어 누름 | 크랙 없음. 저역 마찰음 | "뽀득" |

간격은 균등이 아니라 **지수분포**로 뽑는다. 균등 간격이면 기계음으로 들린다.

### 스테레오

터치 x좌표 → 팬. 이어폰을 끼면 손가락을 따라 소리가 좌우로 움직인다.
ASMR에서 공간감은 음색만큼 중요하다. 첫 실행 때 이어폰 권장 안내를 1회 띄운다.

### 진동

그레인 밀도에 맞춰 짧은 햅틱을 같이 쏜다(초당 최대 40회로 제한, 그 이상은 뭉개짐).
`VibratorManager` + `VibrationEffect.createOneShot`. 설정에서 끌 수 있다.

### 튜닝 방법

합성 파라미터를 감으로 정하면 "플라스틱 부서지는 소리"가 나온다. 그래서:

1. 실제 왁뿌볼 ASMR 자료를 조사해 **수치 기준**을 먼저 확보한다 —
   크랙 간격 분포, 지배 주파수 대역, 감쇠 시간, 재질별 차이.
   오디오 파일을 가져다 쓰는 게 아니라 특성값만 참고하므로 저작권 문제가 없다.
2. 그 기준에 맞춰 파라미터를 잡고, 오프라인 렌더 → 스펙트럼·RMS·크랙 밀도를 자동 검증한다.
3. 최종 검수는 귀다. 빌드해서 들어보고 반복 조정한다. 한 번에 끝나지 않는다.

## 5. 볼과 깨짐

### 3겹 구조

```
바깥: 왁스 껍질   shard 80~300개. 깨지는 대상
중간: 속살        껍질이 벗겨지면 드러남. 볼마다 색이 다름
안쪽: 말랑이 코어  누르면 눌리고 되돌아옴 (버텍스 셰이더 변형). "뽀득" 소리
중심: 캡슐        도감 아이템 1개. 완파해야 나옴
```

### 조각 분할

격자로 자르면 바둑판처럼 보여 가짜 티가 난다. 구 표면에 점을 불규칙하게 뿌리고
그 영역대로 자른다(구면 보로노이). **시드는 매번 랜덤** — 같은 볼을 두 번 깨도
갈라지는 모양이 다르다.

### 파괴 상태머신

```
INTACT → HAIRLINE → CRACKED → LOOSE → DETACHED
```

- 터치가 닿아 있는 동안 해당 shard에 압력이 누적된다(초당 압력 × 접촉 면적)
- 임계를 넘을 때마다 다음 단계로 전이하고, 전이할 때 BreakEvent를 낸다
- **균열 전파**: 전이가 일어나면 인접 shard에 압력의 30~50%가 전달된다.
  한 곳을 세게 누르면 옆 조각까지 실금이 가고, 다음에 건드리면 우수수 떨어진다.
  이게 "깨는 맛"의 정체다. 전파 계수는 재질별로 다르다(하드왁스 높음, 소프트왁스 낮음).
- 낮은 단계로 되돌아가지 않는다(비가역).

### 떨어진 조각

사라지지 않는다. 중력·회전으로 떨어져 화면 아래에 쌓인다. 부스러기가 점점 쌓이는 게
눈에 보이는 것이 진행감이다. 폰을 흔들면 치워진다(가속도 센서).
최대 400조각까지 유지하고 초과분은 오래된 것부터 페이드아웃한다.

### 조작

| 동작 | 결과 |
|---|---|
| 볼 위 한 손가락 탭 | 그 지점 깨기 |
| 볼 위 길게 누름 | 압력 누적, 연속 크랙 |
| 볼 위 드래그 | 지나간 자리가 줄줄이 까임 (핵심 동작) |
| 볼 **바깥** 여백 드래그 | 볼 굴리기 |
| 두 손가락 드래그 | 어디서든 굴리기 |
| 핀치 | 확대/축소 |
| 폰 흔들기 | 부스러기 치우기 |

깨기와 굴리기의 충돌은 **볼 안/밖**으로 나눠 해결한다. 그래도 헷갈릴 사용자를 위해
우측 하단에 굴리기 잠금 토글을 둔다.

### 볼 30종 — 4축 조합

| 축 | 값 | 소리에 미치는 영향 |
|---|---|---|
| 크기 | 소/중/대/특대 | 클수록 저음↑ 여운↑, 조각 수↑ |
| 껍질 두께 | 얇음/보통/두꺼움 | 두꺼우면 저역 "뽀각", 얇으면 고역 "바스락" |
| 모양 | 구/달걀/각진/울퉁불퉁 | 각진 볼은 모서리 shard부터 잘 깨짐 |
| 재질 | 하드왁스/소프트왁스/글리터/크런치비즈/설탕유리 | 주파수 대역·크랙 밀도·전파 계수가 통째로 바뀜. **체감 차이 가장 큼** |

각 볼은 색만 다른 게 아니라 **소리 파라미터 세트가 다르다.** 도감에 소리 설명이 붙는다.
기본 해금 5종, 나머지 25종은 코인으로 해금.

## 6. 모드

세 모드 모두 같은 `PlayActivity`를 쓴다. 미션 모드는 씬에 판정기를 붙였다 뗄 뿐이고,
파괴·소리 코드는 건드리지 않는다. 미션을 만들다 샌드박스가 망가지는 사고를 막기 위해서다.

### 샌드박스 (본체)
목표·점수·타이머 없음. 다 까면 3초 뒤 새 볼이 굴러 들어온다.
UI는 3초 무입력 시 사라진다. 무한 반복이 기본 상태다.

### 미션
일일 3개가 랜덤 배정된다(자정 기준 갱신). 6종 풀:

1. **속도** — 제한시간 안에 껍질 N% 까기
2. **한 획** — 손 떼지 않고 한 번의 드래그로 조각 N개 분리
3. **정밀** — 최대 압력을 넘기지 않고 완파 (세게 누르면 실패)
4. **사방** — 볼을 굴려가며 4분면 각각 60% 이상 까기
5. **콤보** — 크랙이 N초 동안 한 번도 끊기지 않게 유지
6. **껍질만** — 코어를 한 번도 누르지 않고 껍질 100% 제거

클리어 시 코인 보상. 실패해도 페널티 없이 다시.

### 도감
볼 30종 그리드. 완파한 볼은 컬러 + 안에서 나온 캡슐 아이템 + 소리 프로파일 설명.
미완파는 실루엣. 카드를 누르면 그 볼로 바로 플레이.

### 경제
코인 = 분리한 조각 수 ÷ 10 + 완파 보너스 20 + 미션 보상 30~80.
용처는 볼 해금뿐이다. 소모품·광고·과금 없다.

## 7. 저장

`SharedPreferences`("waxball") 하나. JSON 문자열 한 덩어리로 저장한다.
저장 대상: 코인, 해금한 볼 id, 도감 완파 기록, 오늘의 미션과 진행, 설정값.
`Progress`는 순수 데이터 클래스이고 저장소는 인터페이스로 분리해 JVM에서 테스트한다.

## 8. 성능

- 목표 60fps. shard는 인스턴싱으로 한 번에 그린다.
- 기기 성능에 따라 shard 수를 조정한다: 첫 실행 시 5초간 프레임타임을 재서
  상/중/하 등급을 정하고 볼당 최대 shard 수를 300/180/100으로 제한한다.
- 오디오 동시 그레인 수 상한 256. 넘치면 가장 오래되고 조용한 것부터 뺏는다(voice stealing).
- 오디오 언더런이 감지되면 버퍼를 1회 키우고 로그를 남긴다.

## 9. 에러 처리

| 상황 | 대응 |
|---|---|

## 10. 테스트 전략

**JVM 유닛테스트 (PC에서 자동 실행)** — 여기가 앱의 본체다.
- `Icosphere`: 정점 수·반지름·중복 정점 없음
- `ShardSplitter`: 모든 shard 면적 합 = 구 표면적(오차 1%), 인접 그래프 대칭성, 고아 shard 없음
- `BreakModel`: 상태 전이 순서, 비가역성, 균열 전파량, 이벤트 방출 횟수,
  랜덤 입력 1000회 후에도 상태 불변식 유지
- `Synth` 오프라인 렌더: 그레인 밀도가 압력에 비례하는지, 재질별 스펙트럼 중심이
  설계값 대역에 들어오는지, 클리핑(|x|>1) 없는지, 무음 구간에 DC 오프셋 없는지
- `Missions`: 6종 판정기 각각의 성공/실패 경계
- `Progress`: 코인 계산, 해금, 저장·복원 왕복
