# AR 손바닥 모드 — 설계 문서

작성일 2026-07-26

## 1. 무엇을 만드는가

카메라로 손바닥을 비추면 그 위에 왁뿌볼이 올라오고, **손을 쥐면 쥔 만큼 부서진다.**

기존 모드는 화면 속 볼을 손가락으로 문질러 깬다. 이 모드는 진짜 손 위에 올려놓고
진짜로 쥐어서 으스러뜨린다. 실제 왁뿌볼을 쥐는 동작 그대로다.

성공 기준: **손을 쥐었을 때 손 안의 것이 으스러지는 느낌이 나야 한다.**
소리와 파괴는 이미 완성돼 있으므로, 이 모드가 더할 것은 "내 손 위에 있다"는 감각뿐이다.

## 2. 왜 ARCore가 아니라 손 인식인가

ARCore는 바닥·벽 같은 평면을 잡는 도구다. 손은 못 본다.
손바닥 위에 올리려면 손 관절을 직접 인식해야 하므로 MediaPipe Hand Landmarker를 쓴다.

부수적으로 얻는 것이 있다. **ARCore가 필요 없어진다.**
테스트 기기(SM-G988N)에 Google Play 서비스(AR)가 설치돼 있지 않아 ARCore 방식은
사용자가 별도 설치를 해야 했는데, 이 제약이 사라진다.

## 3. 구조

새로 만드는 것은 `ar/` 하나다. 나머지는 전부 기존 것을 그대로 쓴다.

```
ar/
  HandTracker      카메라 프레임 → 손 관절 21개. MediaPipe 래퍼
  PalmPose         관절 → 볼 위치·크기·쥐는 세기. 순수 계산이라 PC에서 검증한다
  ArPlayActivity   카메라 미리보기 + 그 위에 투명 GL 화면
  ArPlayView       투명 배경 GLSurfaceView
```

**손대지 않는 것**

| 재사용 | 이유 |
|---|---|
| `BreakModel` | 쥐는 세기를 힘으로 넣으면 끝. 파괴 규칙은 그대로 |
| `Synth`·`GrainBank`·`AudioEngine` | 소리는 이미 녹음 파편 재생으로 완성돼 있다 |
| `BallGeometry`·`ShardSplitter` | 볼과 조각 생성 동일 |
| `Debris` | 떨어진 조각 낙하·누적 동일 |
| `BallRenderer` | 행렬을 받아 그리는 구조라 카메라 자세만 바꿔 끼운다 |

`Weapon`은 쓰지 않는다. AR에서는 손 자체가 도구이므로 도구 선택 줄도 띄우지 않는다.

파괴·소리 쪽은 **한 줄도 고치지 않는다.** 이 모드가 하는 일은 손 좌표를 볼의
위치·크기·힘으로 번역하는 것뿐이다.

### 화면 합성

CameraX `PreviewView`를 아래에 깔고 그 위에 투명 배경 `GLSurfaceView`를 얹는다.
카메라 텍스처를 직접 GL로 그리지 않는다. 직접 그리면 색공간 변환과 회전 처리를
전부 떠안아야 하는데, 얻는 것이 없다.

- GL 표면: `setEGLConfigChooser(8,8,8,8,16,0)`, `setZOrderMediaOverlay(true)`,
  `holder.setFormat(TRANSLUCENT)`, `glClearColor(0,0,0,0)`

## 4. 손을 볼로 바꾸는 계산

`PalmPose`가 하는 일 전부다. 안드로이드 API를 쓰지 않아 PC에서 검증된다.

### 위치

손목(0), 검지뿌리(5), 새끼뿌리(17) 세 점의 평균이 손바닥 한가운데다.
이 세 점은 손을 쥐어도 거의 안 움직여서, 쥐는 동안 볼이 흔들리지 않는다.
손가락 끝을 쓰면 쥘 때마다 볼이 딸려 들어간다.

그 화면 좌표로 광선을 쏴서 고정 거리에 볼을 놓는다. `BallRenderer.screenToRay`를 그대로 쓴다.

### 크기

검지뿌리(5)와 새끼뿌리(17) 사이 거리가 손 너비다. 여기에 비례해 볼 반지름을 정한다.
손을 카메라에 가까이 대면 손 너비가 커지고 볼도 같이 커진다.

볼이 손을 벗어나 보이지 않도록 손 너비의 0.9배로 잡는다.

### 쥐는 세기

손가락 네 개(검지·중지·약지·새끼)의 굽힘을 평균낸다.

```
손가락 하나의 굽힘 = 1 - (손목→손가락끝 거리) / (손목→손가락뿌리 거리 × 펴진길이비)
편 손 → 0, 주먹 → 1
```

거리 비율로 재기 때문에 손이 카메라에서 멀어져도 값이 흔들리지 않는다.
각도로 재면 손을 기울일 때마다 값이 튄다.

### 떨림 죽이기

관절 인식은 프레임마다 미세하게 떨린다. 위치·크기·쥐는 세기 전부 지수 평활을 건다.

```
출력 = 출력 × (1 - α) + 입력 × α      α ≈ 0.35
```

평활이 없으면 볼이 계속 지글거리고, 쥐는 세기가 튀어서 안 쥐었는데도 부서진다.

## 5. 쥐면 부서지는 것

쥐는 세기를 `BreakModel.pressArea`에 넣는다. 손가락 하나로 콕 누르는 것이 아니라
**카메라 쪽 반구 전체를 한꺼번에** 누른다. 손에 쥐면 닿는 면 전체가 으스러지기 때문이다.

```
힘 = 쥐는세기^1.5 × 4.5
접촉 범위 = 카메라 방향 기준 반구 (contactCos ≈ 0.1)
```

지수를 1.5로 두는 이유는, 살짝 쥐었을 때는 거의 안 부서지고 꽉 쥐어야 우수수
떨어지게 하기 위해서다. 선형이면 손을 조금만 움직여도 계속 부서져서 조절이 안 된다.

세게 쥐면 나머지는 이미 만들어둔 것들이 따라온다. 넓은 판이 떨어지고, 연쇄가 일어나고,
화면이 흔들리고, 진동이 오고, 소리가 난다.

**쥐었다 폈다를 반복하는 것이 이 모드의 기본 동작이다.** 계속 쥐고만 있으면
가만히 있어도 볼이 계속 무너져서 조작하는 느낌이 사라진다.

그래서 **쥐는 세기가 늘어나는 동안에만** 힘을 준다. 세기가 그대로거나 줄면 힘은 0이다.

```
힘 = max(0, 이번 쥠 - 지난 쥠) × 60 × 쥔세기^0.5
```

`× 60`은 초당 프레임 수를 곱해 프레임 속도와 무관하게 만들기 위한 값이다.
뒤의 `쥔세기^0.5`는 이미 꽉 쥔 상태에서 더 조일 때 더 세게 들어가게 한다.

## 6. 알려진 한계

**손가락이 볼을 가리지 못한다.** 볼이 항상 손 위에 덧그려진다. 손가락을 볼 앞으로
가져가도 볼이 위에 뜨기 때문에, 진짜로 쥐고 있다기보다 "붙여놓은" 느낌이 난다.
제대로 하려면 손 실루엣으로 가려내야 하는데 작업량이 몇 배가 된다. 이번 범위에서 제외한다.

**어두운 방이나 빠른 움직임에서는 인식이 흔들린다.** 평활이 어느 정도 흡수하지만
한계가 있다. 심하면 손을 놓친 것으로 처리한다.

## 7. 실패 처리

| 상황 | 대응 |
|---|---|
| 카메라 권한 거부 | 안내 후 기존 모드로 돌아간다. AR을 강요하지 않는다 |
| 카메라 없음 / 열기 실패 | 같음 |
| 인식 모델 로드 실패 | 같음. 앱이 죽지 않는 것이 우선 |
| 손을 놓침 | 볼을 마지막 자리에 멈춰두고 "손바닥을 펴서 보여주세요" 안내 |
| 손이 두 개 이상 | 가장 큰 손 하나만 쓴다 |
| 볼 완파 | 기존 모드와 동일하게 2.6초 뒤 새 볼 |
| 화면 회전 | 세로 고정이므로 발생하지 않는다 |

## 8. 검증

**JVM 유닛테스트** — `PalmPose`가 전부다. 관절 좌표를 직접 넣어 확인한다.

- 편 손 → 쥠 0에 가깝고, 주먹 → 1에 가깝다
- 편 손에서 주먹까지 단계별로 넣으면 쥠 값이 단조 증가한다
- 손이 카메라에 가까울수록(관절 간격이 넓을수록) 볼 크기가 커진다
- 손을 기울이거나 회전시켜도 쥠 값이 크게 변하지 않는다
- 좌표를 한 프레임 크게 튀게 해도 평활 뒤 출력이 급변하지 않는다
- 관절이 일부만 잡힌 입력에서도 예외 없이 값을 낸다
- 쥔 상태를 유지하면 힘이 0이 된다(가만히 있는데 계속 부서지지 않는다)
- 쥐었다 폈다를 반복하면 반복할 때마다 힘이 들어간다

**실기기 확인** — 카메라·인식·체감은 기기로만 확인된다.

- 손 위에 볼이 붙어 따라다니는가
- 쥐었을 때 실제로 으스러지는 느낌이 나는가
- 조명이 어두울 때 쓸 만한가
- 카메라 + 인식 + 렌더를 동시에 돌릴 때 프레임이 버티는가

## 9. 늘어나는 것

| | 크기 |
|---|---|
| 손 인식 모델 (`hand_landmarker.task`) | 약 8MB |
| MediaPipe tasks-vision | 약 4MB |
| CameraX | 약 2MB |

APK가 9.3MB에서 **20MB 안팎**이 된다.

배터리와 발열도 늘어난다. 카메라·머신러닝·GL을 동시에 돌리기 때문이다.
기존 모드는 그대로 두므로, 오래 놀 때는 기존 모드를 쓰면 된다.

## 10. 범위 밖

- 손 실루엣으로 볼을 가리는 처리(오클루전)
- 두 손 동시 인식
- 평면 인식·공간 앵커(ARCore)
- 손 그림자·반사 같은 조명 합성
- AR 모드 전용 미션·도감
