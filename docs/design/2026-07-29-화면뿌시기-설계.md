# 화면 뿌시기 모드 — 설계

## 왜 하는가

왁뿌볼을 깨는 것과 별개로, **눈앞에 보이는 것을 그냥 깨부수는** 스트레스 해소용 모드가
있으면 좋겠다는 요청이다. 카메라로 한 장 찍고 그 사진을 손가락으로 깨부순다.

손바닥 모드가 겪은 문제를 피해 간다. **손 인식이 필요 없다.** 화면을 손가락으로
만지는 것이므로, 굽힘 비율이나 쥠 판정 같은 것이 끼어들 자리가 없다.

**기존 왁뿌볼 파괴는 한 줄도 건드리지 않는다.** 새 화면을 하나 더 만드는 것이고,
기존 파일 중 손대는 것은 홈 화면 버튼과 문자열뿐이다.

## 무엇을 만드는가

```
홈 → "화면 뿌시기"
  → 카메라로 한 장 찍고 즉시 카메라를 놓는다
  → 그 사진이 화면을 꽉 채운다
  → 손가락으로 문지르면 그 자리가 깨져 조각이 떨어진다
  → 조각은 아래에 쌓인다. 쌓인 것도 문지르면 더 잘게 부서진다
  → 다 깨면 2.6초 뒤 새로 찍는다. "다시 찍기" 버튼으로 언제든 새로 찍는다
```

**얼려붙인 한 장만 쓴다. 실시간 영상은 쓰지 않는다.** 실시간으로 하려면 카메라를
`GL_TEXTURE_EXTERNAL_OES`로 받는 배선을 새로 깔아야 하는데, 얻는 것에 비해 몇 배로 크다.
한 장이면 평범한 GL 텍스처 하나로 끝난다. 깨진 틈으로 정지 화면이 보이는 것이
유리 깨지는 느낌에도 더 가깝다.

## 기존 것을 어디까지 쓰는가

이 설계의 요점은 **거의 다 이미 있다는 것**이다.

| 그대로 쓰는 것 | 무엇을 해 주나 |
|---|---|
| `core/BreakModel` | 손상 누적, 금 전파, 연쇄 붕괴, 소리 이벤트, 분리음 묶기 |
| `core/ShardSet`·`Shard` | 조각 집합과 인접 관계를 담는 그릇 |
| `gl/Debris` | 낙하, 바닥에 쌓임, 문질러 더 잘게 부수기 |
| `audio/Synth`·`AudioEngine` | 소리 전부 |
| `audio/Haptics` | 진동 |
| `ui/Insets` | 시스템 바 회피 |

**`BreakModel`은 수정 없이 쓴다.** 조각 하나를 누르는 `press(shardId, force, dt, pan)` 가
이미 공개돼 있고, 그 안에서 금 전파와 연쇄가 전부 돈다. 평면 모드는 손가락 반경 안의
조각을 직접 골라 `press` 를 부르면 된다. 구면 전용인 것은 `pressArea` 하나뿐이라 안 쓴다.

초기화 때 `quadrantIndex(center)` 가 조각마다 한 번 도는데, 평면 좌표(`z = 0`)에서도
안전하게 계산된다. 그 값은 4분면 미션에서만 쓰이고 이 모드는 미션을 쓰지 않는다.

## 조각 나누기

새 파일 `core/PlaneSplitter.kt`. 안드로이드 API를 쓰지 않아 PC에서 검증한다.

화면에 시드를 흩뿌리고, 시드마다 화면 사각형을 **다른 시드와의 수직이등분선으로 잘라내**
셀을 만든다(반평면 클리핑 보로노이). 시드 140개면 클리핑이 2만 번인데, 폴리곤 정점이
몇 개뿐이라 로딩 때 백그라운드 스레드에서 끝난다. 손바닥 모드가 볼을 만드는 방식과 같다.

**크기를 일부러 들쭉날쭉하게 만든다.** 조각이 다 똑같으면 깨는 맛이 없다는 것을 이미
겪었고, `ShardSplitter` 가 같은 이유로 그렇게 돼 있다. 시드의 20%는 화면 전체에 넓게,
80%는 몇 군데에 몰아 뿌려서 큰 판과 잔조각이 섞이게 한다.

출력은 셀 폴리곤(정규 화면 좌표 0~1) + 면적비 + 인접 관계다. 인접은 클리핑 과정에서
실제로 변을 만든 상대만 이웃으로 잡는다. 이걸 그대로 `ShardSet` 에 담는다.

## 깨기

손가락 좌표에서 반경 안의 조각을 골라, 거리에 따라 힘을 나눠 `model.press(id, ...)` 를
부른다. 문지르면 지나간 자리가 줄줄이 까이고, 한 자리를 계속 누르면 깊게 파인다.
좌우 위치가 그대로 소리의 팬이 된다.

**스트레스 해소용이라 왁뿌볼보다 잘 깨져야 한다.** 소리는 설탕유리가 유리 깨지는 쪽에
가장 가까운데 단단함이 1.25로 높다. `SoundProfile` 이 data class이므로
`sugarGlass().copy(toughness = 0.55f)` 로 그 값만 낮춘 사본을 쓴다.

## 구조

**새로 만드는 것**

| 파일 | 책임 | 의존 |
|---|---|---|
| `core/PlaneSplitter.kt` | 화면을 불규칙 조각으로 나눈다 | 없음 (순수 Kotlin) |
| `gl/PlaneGeometry.kt` | 셀 폴리곤 → 삼각형 + UV | `PlaneSplitter` 결과 |
| `gl/SmashRenderer.kt` | 사진 텍스처와 조각을 그린다 | `PlaneGeometry`, `Debris` |
| `ui/SmashView.kt` | GL 뷰 | `SmashRenderer` |
| `ui/SmashActivity.kt` | 위를 엮는 배선 | 전부 |

**고치는 것**: `ui/HomeActivity.kt`(버튼 하나), `res/layout/activity_home.xml`,
`res/values/strings.xml`. 그 외 기존 파일은 건드리지 않는다.

## 데이터 흐름

```
카메라 첫 프레임 → Bitmap → GL 텍스처 (그 뒤 카메라를 놓는다)
PlaneSplitter → 셀 폴리곤 · 면적비 · 인접
  → ShardSet → BreakModel
손가락 좌표
  → 반경 안의 조각 선별
  → BreakModel.press(id, 힘, dt, 팬)
  → EventQueue → Synth → 소리
  → 떨어진 조각 → Debris → 낙하 · 쌓임
PlaneGeometry + Debris 변환 → SmashRenderer
```

## 실패 처리

- **카메라 권한이 없거나 카메라를 못 열면** 어두운 그라데이션 화면을 깬다. 손바닥 모드는
  카메라가 없으면 기존 모드로 돌려보내지만, 여기는 깨는 것이 목적이므로 계속 간다.
- **사진을 못 찍으면** 같은 대체 화면을 쓴다. 화면이 안 뜨는 것보다 낫다.
- **부스러기는 조각 수만큼만 쌓인다.** 조각 번호와 슬롯이 1:1이라 무한정 늘지 않는다.
- **다 깨진 뒤** 2.6초 동안은 부스러기를 그대로 두고 본다. 그 뒤 새로 찍는다.

## 테스트

전부 PC에서 도는 JVM 테스트다. 카메라도 기기도 필요 없다.

| 무엇을 | 어떻게 |
|---|---|
| 조각이 화면을 빈틈없이 덮는가 | 면적비 합이 1인지 |
| 조각끼리 겹치지 않는가 | 무작위 점 1000개가 각각 정확히 한 셀에만 들어가는지 |
| 인접 관계가 대칭인가 | a가 b의 이웃이면 b도 a의 이웃인지 |
| 크기가 들쭉날쭉한가 | 가장 큰 조각이 중앙값의 몇 배인지 |
| 셀이 화면 밖으로 안 나가는가 | 모든 정점이 0~1 안인지 |
| 만진 자리만 깨지는가 | 한쪽을 누르고 반대쪽이 멀쩡한지 |
| 문지르면 지나간 자리가 까이는가 | 가로로 훑고 그 띠만 깨졌는지 |

## 하지 않는 것

- **실시간 카메라 영상.** 얼려붙인 한 장만 쓴다
- **미션·기록·콤보.** 스트레스 해소용이라 목표를 두지 않는다
- **왁뿌볼 모드 변경.** 기존 파괴·소리 경로는 건드리지 않는다
- **깨진 틈으로 다음 사진 보여주기.** 조각이 떨어진 자리는 검은 바닥이다
