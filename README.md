# 왁뿌볼 ASMR

왁스 뿌시기 볼을 화면에서 굴리고 문질러 까면서, 그때 나는 "빠자자작" 소리를 듣는
안드로이드 촉감·ASMR 앱.

성공 기준은 하나다. **눈 감고 소리만 들었을 때 진짜 왁뿌볼 부수는 소리로 들려야 한다.**
그래픽·미션·수집은 전부 그 소리를 계속 듣게 만들기 위한 장치다.

---

## 무엇을 하는 앱인가

3D 왁스볼을 손가락으로 만지면 그 자리가 깨진다. 세게 누르면 깊게, 쭉 문지르면 줄줄이.
금은 옆 조각으로 번지고, 떨어진 조각은 바닥에 쌓인다. 껍질을 다 벗기면 안쪽 말랑이가
드러나고, 가운데에서 도감 아이템이 나온다.

- **샌드박스** — 목표도 점수도 없다. 다 까면 새 볼이 굴러온다. 이게 본체다
- **미션** — 매일 3개. 속도·한 획·정밀·사방·콤보·껍질만
- **도감** — 볼 30종. 완파하면 안에서 나온 아이템과 소리 설명이 채워진다

## 조작

| 동작 | 결과 |
|---|---|
| 볼 위 한 손가락 탭 | 그 지점 깨기 |
| 볼 위 길게 누르기 | 힘이 쌓이며 연속 크랙 |
| 볼 위 드래그 | 지나간 자리가 줄줄이 까임 |
| 볼 **바깥** 여백 드래그 | 볼 굴리기 |
| 두 손가락 드래그 | 어디서든 굴리기 |
| 핀치 | 확대·축소 |

깨기와 굴리기가 서로 먹지 않게 볼 안/밖으로 영역을 나눴다. 그래도 헷갈리면
우측 하단 "굴리기 잠금"을 켜면 화면 전체가 깨기 영역이 된다.

## 소리를 어떻게 만들었나

**녹음 파일을 하나도 쓰지 않는다.** 앱 안에 오디오 애셋이 없다.
몇 번만 들으면 귀가 "아까 그 소리"라고 알아채는 순간 ASMR이 죽고,
손가락 힘에 따라 소리가 변할 수도 없기 때문이다.

### 그래뉼러 크랙 합성

실제 왁스 파쇄음은 한 번의 "빵"이 아니다. 아주 작은 파열 수백 개가 불규칙한 간격으로
연달아 터지는 소리다. 그래서 "빠자자작"으로 들린다. 이걸 그대로 모사한다.

```
그레인 1개 = 대역통과된 노이즈 순간 폭발 + 짧게 울리는 공명음
  · 어택 0.4ms 이하 — 딱 하고 서는 앞머리가 파쇄음의 정체다
  · 감쇠 4~40ms — 주파수에 따라 달라진다(아래 참조)
  · 중심 주파수 800Hz ~ 9kHz — 재질이 결정한다
파괴 이벤트 1개 = 이 그레인 5~200개를 지수분포 간격으로 흩뿌림
```

간격을 균등하게 두면 기계음으로 들린다. **지수분포여야 진짜 파쇄음이 된다.**

### 손가락 힘이 소리를 바꾼다

| 행동 | 결과 |
|---|---|
| 살살 탭 | 그레인 5~20개, 평균 6ms 간격. "빠… 빠작" |
| 꾹 누르기 | 그레인 200개, 평균 1.2ms 간격. "빠자자자작" |
| 문지르기 | 속도에 비례해 계속 방출 |
| 큰 조각 분리 | 낮고 여운이 긴 "뽀각" 뒤에 밝은 부스러기가 뒤따른다 |
| 코어 누르기 | 크랙 없이 220~480Hz 마찰음만. 어택 7ms로 둔하게 |

### 점탄성 감쇠

파라핀 왁스처럼 무른 재질에서는 **고주파 성분이 먼저 급격히 사라지고 저주파만 남는다**
([취성 파괴의 음향 방출 연구](https://arxiv.org/pdf/1811.03072)).
그래서 그레인의 감쇠 시간을 중심 주파수 대비 `sqrt(baseFreq / freq)` 로 보정한다.
이 보정이 없으면 파쇄음이 아니라 잡음 뭉치처럼 들린다.

### 실측으로 잡은 값 (2026-07-26)

직접 녹음한 왁뿌볼 영상 세 개를 분석해 프로파일을 다시 잡았다. 감으로 잡았던 처음 값은
네 가지가 크게 틀렸다.

| | 처음 (감) | 녹음 실측 |
|---|---|---|
| 음높이 산포 | 0.8 옥타브 | **1.5~2.1 옥타브** |
| 파열 간격 | 1.2~6ms | **81~208ms (귀에 들리는 단위)** |
| 저역 비중 | 0% | **6~21%** |
| 평탄도 | 잡음에 가까움 | **0.18~0.31 (음정이 있는 쪽)** |

종류가 다른 세 개라 재질별 성격도 추측이 아니라 실측으로 나눌 수 있었다.
왁뿌볼2는 성기고(간격 208ms) 음정감이 가장 강했고(0.18), 왁뿌볼3은 압도적으로 밝았다
(중심 6253Hz, 고역 74%).

**주의**: 녹음에는 폰 마이크 특성·방 울림·AAC 압축이 섞여 있다. 스펙트럼 수치를 1:1로
맞추려 들면 마이크를 흉내 내게 된다. 큰 방향(파열 밀도, 산포, 저역 유무, 음정감)까지만
수치로 맞추고 나머지는 귀로 판단한다.

### 실제 녹음에서 파라미터 뽑기

귀로 "좀 더 낮게"를 반복하는 것보다 정답지의 수치를 재서 맞추는 편이 빠르다.
실제 왁뿌볼을 녹음한 WAV를 `app/reference/` 에 넣고 `test.bat`을 돌리면
파열 빈도·간격·스펙트럼 중심·산포·감쇠 시간·대역 분포·평탄도를 재서,
그대로 붙여 넣을 수 있는 `SoundProfile` 초안을 `app/build/reference-report.txt` 에 써 준다.

분석기 자체는 정답을 아는 합성 신호(간격 60ms·2kHz 클릭 열 등)로 검증한다.
녹음이 없으면 이 단계는 조용히 건너뛴다.

### 재질 5종

| 재질 | 중심 주파수 | 성격 |
|---|---|---|
| 굳은 왁스 | 2600Hz | 기준이 되는 소리. 마르고 단단한 빠작 |
| 무른 왁스 | 1300Hz | 낮고 둔한 뿌직. 금이 잘 안 번진다 |
| 반짝이 왁스 | 3800Hz | 자잘하고 밝은 사각사각 |
| 알갱이 왁스 | 1900Hz | 그레인이 제일 많아 길게 이어진다 |
| 설탕 유리 | 5200Hz | 가장 높고 뾰족하며 금이 제일 잘 번진다 |

여기에 크기(주파수·여운), 두께(밝기·감쇠·공명), 모양(전파·공명·산포)이 곱해져
볼 30종이 **전부 다른 소리**를 낸다.

### 스테레오와 지연

터치 x좌표가 그대로 팬이 된다. 이어폰을 끼면 손가락을 따라 소리가 좌우로 움직인다.
ASMR에서 공간감은 음색만큼 중요하다.

지연 목표는 **30ms 이하**. 손가락과 소리가 어긋나면 뇌가 가짜로 인식해서
효과가 통째로 사라진다. 기기 네이티브 샘플레이트·버퍼를 그대로 쓰고,
`AudioTrack`을 `PERFORMANCE_MODE_LOW_LATENCY` + `PCM_FLOAT`로 연다.

**오디오 스레드에서는 객체를 하나도 만들지 않는다.** 그레인 상태는 전부 사전 할당된
원시 배열이고, 파괴 이벤트도 객체가 아니라 링 버퍼의 한 줄로 넘긴다.
GC가 오디오 콜백을 한 번 멈추면 소리가 뚝 끊긴다.

## 구조

```
core/     순수 코틀린. 안드로이드 API를 일절 쓰지 않아 PC에서 전부 검증된다
  Icosphere        구 메시 생성
  ShardSplitter    구 표면을 불규칙 조각으로 분할(구면 보로노이)
  BreakModel       파괴 상태머신, 균열 전파
  EventQueue       할당 없는 SPSC 링 버퍼
  BallSpec/Catalog 볼 30종과 소리 매핑
  Mission          미션 6종 판정기
  Progress         코인·해금·도감
audio/
  GrainPool        그레인 합성. 오디오 스레드의 안쪽 루프
  Synth            이벤트 → 그레인 스케줄링
  AudioEngine      AudioTrack 출력 스레드
gl/
  BallGeometry     조각 메시(바깥면·안쪽면·측면)
  BallRenderer     OpenGL ES 3.0 렌더러
  Picker           광선 → 조각 선택
  Debris           떨어진 조각 낙하·누적
ui/                화면 4개와 터치 라우팅
```

파괴 로직과 소리는 `BreakEvent` 하나로만 연결된다. 렌더러와 합성기는 서로를 모른다.
덕분에 소리만 따로 검증할 수 있고, 소리를 고쳐도 그래픽이 안 깨진다.

### 조각을 어떻게 나누나

구면을 직접 자르지 않는다. 세분화된 구 메시(5120삼각형)의 각 삼각형을 가장 가까운
시드에 배정해 군집을 만든다. 격자 무늬가 생기지 않고 축퇴 폴리곤 같은 기하 예외가
원천적으로 없다. **시드는 매번 새로 뽑기 때문에 같은 볼을 두 번 깨도 갈라지는 모양이 다르다.**

### 금은 어떻게 그리나

별도 텍스처를 쓰지 않는다. 금이 갈수록 조각을 자기 중심 쪽으로 0~3% 줄인다.
조각 사이에 틈이 벌어지고, 그게 눈에는 금으로 보인다.

조각별 변환은 유니폼 배열 대신 **부동소수점 텍스처**로 넘긴다.
ES 3.0이 보장하는 유니폼 vec4 개수(224)로는 조각 300개를 못 담기 때문이다.

### 개발 중 잡은 문제와 원인

**빌드 환경**

- *Gradle 테스트 워커가 클래스를 못 찾음* — 사용자 홈 경로에 한글이 있어 클래스패스 인자
  파일이 UTF-8로 쓰이고 `java.exe`가 시스템 코드페이지로 읽었다. 정션을 걸어도 Gradle이
  실제 경로로 되돌려서 무용지물. ASCII 경로에 진짜 Gradle 홈을 따로 두어 해결
- *`.bat` 파일이 첫 줄부터 실패* — 주석을 한글로 썼더니 cmd가 파싱하지 못했다. ASCII로 교체
- *리소스 링크 실패 `attr/?? not found`* — 문자열 값 `???` 를 aapt가 테마 속성 참조로
  읽었다. `\?\?\?` 로 이스케이프
- *에뮬레이터가 뜨지 않음* — SDK 자체가 한글 경로에 있어 qemu 백엔드가 인자를 받지 못하고
  즉시 종료. SDK를 통째로 옮겨야 해서 실기기로 검증했다

**설계·구현**

- *볼 두 종의 소리가 완전히 겹침* — 모양이 소리에 반영되지 않아 노른자와 달걀이 같은
  프로파일이었다. 모양별로 금 전파·공명·음높이 산포를 부여해 30종 전부 구분되게 했다
- *코어 마찰음이 지나치게 밝음* — 어택이 0.4ms로 고정이라 저역 그레인에도 광대역 클릭이
  섞였다. 어택을 그레인 파라미터로 빼고 마찰음은 7ms로
- *볼이 화면 가로를 넘겨 잘림* — 카메라 거리를 세로 기준으로 잡아 세로 화면에서 좌우가
  잘렸다. 굴리기용 여백까지 사라졌다. 짧은 축의 82%에 맞추도록 수정
- *파열 하나를 두 번 셈* — 온셋 검출에 재무장 조건이 없어 간격이 절반으로 측정됐다.
  히스테리시스 추가
- *조용한 구간에서 잡음을 파열로 셈* — 이동 중앙값이 0으로 내려앉아 임계가 무너졌다.
  전역 하한 추가

### 교훈

- **측정할 수 없는 것은 테스트하지 말 것.** 초당 800회 파열을 완성된 소리에서 되짚어 세는
  것은 신뢰할 수 없었다. 스케줄러가 정한 값을 직접 검증하는 쪽으로 바꾸니 명확해졌다
- **테스트가 틀릴 수도 있다.** 미션 테스트 3건이 실패했을 때 원인은 구현이 아니라 테스트
  설정이었다. 균열 전파 때문에 의도보다 많은 조각이 떨어졌고, 누르는 패턴이 실제 플레이와
  달랐다
- **예상과 반대인 측정값을 그대로 받아들일 것.** 큰 조각이 떨어질 때 여운이 앞머리보다
  밝게 측정됐다. 확인해 보니 낮은 "뽀각" 뒤에 밝은 부스러기가 따라오는 구조라 그게 맞는
  소리였다. 측정에 맞춰 테스트를 고쳤다

## 빌드

```
build.bat      디버그 APK
test.bat       JVM 유닛테스트 188건
```

`build.bat`/`test.bat`은 `GRADLE_USER_HOME`을 ASCII 경로로 바꿔 준다.
사용자 홈 경로에 한글이 있으면 Gradle이 테스트 워커 클래스패스를 UTF-8로 쓰고
`java.exe`가 시스템 코드페이지로 읽어서 클래스패스가 깨진다.

- 요구: compileSdk 36 / minSdk 26, Android Studio 내장 JDK(jbr)
- 외부 의존성은 androidx·material·junit뿐. NDK도, 게임엔진도, 물리엔진도, 오디오 파일도 없다

## 검증

`test.bat`으로 도는 유닛테스트 188건이 파괴 규칙과 합성기 전체를 덮는다.

- 조각 분할: 삼각형 배정 누락·중복 없음, 인접 그래프 대칭, 빈 조각 없음
- 파괴: 상태 비가역성, 균열이 두 겹 밖으로 번지지 않음, 2만 회 무작위 입력 후 불변식 유지
- 합성: 클리핑 없음, DC 오프셋 없음, 재질별 스펙트럼 중심 분리, 같은 이벤트가 두 번 같지 않음
- 미션 6종 각각의 성공·실패 경계, 저장 손상 내성, 성능 등급 판정

`app/build/audition/`에 재질별·동작별 WAV가 매 테스트 실행마다 생성된다.
수치가 통과해도 진짜 왁뿌볼처럼 들리는지는 사람이 판단해야 하기 때문이다.

### 실기기 확인 결과 (Galaxy S20 Ultra, SM-G988N)

- **터치→소리 지연 8.7~12.2ms.** 목표 30ms를 크게 밑돈다.
  기기 네이티브 버퍼가 192프레임(4ms)이라 NDK 없이도 충분했다
  (`WaxBall` 태그로 로그에 찍힌다)
- 파괴·금 번짐·조각 낙하·진동 모두 정상 동작
- 볼이 화면 가로를 넘겨 잘리던 문제 수정 — 짧은 축의 82%에 맞춰 카메라 거리를 잡는다

## 미해결 항목

- **소리가 아직 실제 왁뿌볼과 다르다.** 후보 5종(`app/build/variants/`)을 만들어 비교 중이고,
  실제 녹음을 넣어 파라미터를 뽑는 경로(`app/reference/`)를 준비해 뒀다. 여기가 이 앱의 핵심이라
  이게 맞춰지기 전에는 완성이 아니다
- 조각 300개(왕 크기)에서 60fps가 유지되는지 미측정
- 미션 6종의 난이도가 실제로 적당한지 미검증. 판정 로직은 테스트로 덮여 있지만
  "할 만한가"는 사람이 해 봐야 안다
- 도감 완파 기록이 여러 판에 걸쳐 제대로 쌓이는지 장시간 플레이 미검증
